# Domain docs

O projeto usa um único contexto: `GLOSSARY.md` na raiz
e decisões em `docs/adr/`.

## Antes de explorar

Leia o glossário e os ADRs relevantes à área do trabalho.
Se estiverem ausentes, prossiga silenciosamente.
A skill domain-modeling cria esses documentos conforme
termos e decisões forem definidos.

## Vocabulário

Use os termos definidos no glossário em tickets, propostas,
código e testes. Sinalize lacunas para domain-modeling.

## Decisões

Se uma proposta contrariar um ADR, explicite o conflito
e o motivo para reconsiderar a decisão.
